# Activate resources without GitHub

Students use the default **Activate & status** tab, acknowledge shared credits, and select **Activate resources only**. No repository, GitHub request, repository review, Lab 5 file structure or CI setup is required. Approved Google login and group membership remain mandatory.

The existing six-stage private worker provisions the same isolated group infrastructure: registry, PostgreSQL database, runtime/deployer service accounts, app secrets, placeholder Cloud Run service, migration job and a group log view. The GitHub stage skips WIF pool/provider creation entirely if no verified repository is bound; it still creates the group's log view. The initial placeholder is not the student's application. Students build/deploy their own application using their group's names/runtime identity. The service, job and database are not automatically tailored to a particular application's port or migration tool.

The resource-only runtime identity is null, with a clearly internal `resources:<team_id>` uniqueness key; it is never fabricated as a GitHub ID. Downloads explicitly say GitHub is not connected (`github_connected` must be an explicit true, otherwise it is treated as not connected; the deployer service account is described without GitHub Actions), omit WIF resources and variables, and provide general project/learning guidance instead of mandatory Lab 5 steps. All existing IAM, size, quota, lease, idempotency, membership synchronization and shared-credit controls remain. One bundle per group; this does not allow arbitrary resource creation or per-group spending guarantees.

For the optional Lab 5 adapter, a group can review a public repository later. Once its current resources are ready and its review is prepared, Activate verifies/freezes the actual GitHub repository and owner IDs, checks uniqueness across teams, and queues only stage 6 (index 5) against the existing group resources. The resources stay `ready` throughout: status, step, outputs and created_at are not touched, and `/api/handoff` keeps working (reporting GitHub as not connected) until the link succeeds. The link has its own sub-state (`github_link_status` queued/running/failed, `github_link_error`); a failed link shows a link-specific message, does not turn the activation into `failed`, and is retried by repeating Activate with the same repository or the Retry GitHub link button. Preview mode follows the same transition (resource-only, then attach a repository once ready; a different repository is rejected). Registry, SQL and app-service creation are not repeated. Connecting a different repository to a group already bound remains blocked. An infrastructure-only retry never silently removes an existing GitHub binding.

UI supports EN/TH. Existing Lab 5 review is in its own optional tab. Groups with an old preview plan can upgrade to live resource-only mode. Local preview can simulate resource-only plans; it never creates cloud resources.

Verification: 68 backend tests passed, including PostgreSQL resource-only activation/attach, independent groups without repos, no GitHub calls/WIF creation, existing-repo preservation, quota enforcement, attach timing/uniqueness, same resource identity and final-stage-only connection. Frontend 4 tests passed, including a resource-only JSON handoff without WIF placeholders. Production frontend built. No browser/UI test or disposable live SQL creation was performed for this change; initial provisioning stages and scoped access retain prior actual two-group verification.
